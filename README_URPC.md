# CoT Bridge для URPC (с подменой UID) — v0.2

Этот вариант моста рассчитан на TAK-серверы, которые **ремапят UID** клиента на серверный (как URPC). На «обычных» TAK-серверах (где подмены нет) тоже работает, просто часть сложности избыточна.

## Что такое подмена UID и в чём проблема

URPC — TAK-сервер с включённым «прокси-аккаунт» режимом. Когда клиент подключается со своим cert'ом, **все его исходящие CoT получают серверный UID** (`SERVER-N`), а реальный UID девайса (например `ANDROID-bc4e5f...`) теряется. На приёмной стороне другие клиенты видят его как `SERVER-N`.

Это критично для шлюза:
- Если мост подключён к URPC под **одним** cert'ом и форвардит туда **PLI разных мешевых юзеров**, URPC превратит их всех в `SERVER-bridge`.
- На карте остальных URPC-клиентов **одна иконка прыгает между координатами разных юзеров**.

Стандартное «один gateway-cert на всех» — не работает.

## Решение: federation gateway с N сертами

```
Honor (мешт, cert честный из ATAK на базе) ──┐
                                              │   мешт
Other  (мешт, cert честный из ATAK на базе) ─┤
                                              │
OnePlus (мост) ──┬─ AIDL ──> Meshtastic ──> нода
                 │
                 ├─ TLS под honor.p12  ──┐
                 ├─ TLS под other.p12  ──┤
                 └─ TLS под mycert.p12 ──┴──> URPC
                                              ↓
                                       SERVER-honor, SERVER-other,
                                       SERVER-mycert — каждый свой
```

URPC ремапит UID **на основании cert'а**, а не на основании UID в пакете. Значит каждый cert даёт свой `SERVER-N`. Если мы шлём PLI Honor под honor.p12 — URPC ремапит на `SERVER-honor`. У других на карте — отдельная иконка `SERVER-honor`. Точка не прыгает.

## Шаги установки

### 1. Каждый мешевой юзер получает свой cert от URPC (один раз на базе)

Делается через стандартный TAK enrollment в их собственном ATAK:

1. ATAK → ☰ → Settings → Network Preferences → Manage Server Connections → **Add**.
2. Hostname URPC, port (обычно `8089`), Use Authentication **ON**, ввести `username` / `password` (свои).
3. ATAK выполнит enrollment, получит cert от URPC, сохранит соединение.
4. ATAK → ☰ → Import Manager → **Export** → выбрать этот сервер → **Mission Package** (.zip).
5. Полученный `.zip` (это и есть DataPackage с `client.p12` + `truststore-*.p12` + `*.pref`) **передать тебе** (Telegram, USB, любым способом).

Каждый юзер делает это **один раз** при наличии интернета на базе. После — карточка работает оффлайн, мост на OnePlus делает всё остальное.

### 2. Импорт cert'ов в мост на OnePlus

1. Открой **CoT Bridge** APK.
2. В карточке «Серты мешевых юзеров» нажми **Импорт DataPackage (.zip)**.
3. Выбери `.zip` файл (через файловый пикер Android).
4. **Пароль .p12** — обычно `atakatak`, если у юзера в ATAK не менялся. Если менялся — спроси у владельца.
5. **Callsign** — оставь пустым, мост возьмёт CN из cert'а (обычно совпадает с tactical callsign'ом юзера в его ATAK). Если у юзера в Meshtastic callsign другой — впиши тот, что используется в меше.
6. **URPC host / port** — оставь пустым, мост прочитает из `.pref` файла внутри DataPackage.
7. Нажми **Импорт**. В списке cert'ов появится запись с серым индикатором.

Повтори для каждого мешевого юзера.

### 3. Запуск

- Убедись, что **Meshtastic Android** запущен и нода подключена по BT (зелёный индикатор).
- Убедись, что **ATAK-CIV** на OnePlus подключён к URPC под твоим cert'ом (это твоё штатное соединение — как было до моста).
- Нажми **Старт** в CoT Bridge.
- В карточке «Серты» индикаторы перейдут в жёлтый (соединяюсь) → зелёный (OK). На каждый импортированный cert — отдельная TLS-сессия.

### 4. Проверка

- На стороне **Honor** (другой телефон, ATAK + Meshtastic ATAK Plugin, без интернета) — свои мешевые точки должны быть видны как раньше.
- На стороне любого **другого URPC-клиента** (например, твой второй телефон с ATAK, подключённый к URPC по интернету) — должны появиться **иконки** мешевых юзеров с их callsign'ами. **Каждая отдельная иконка**, не прыгающая.
- Счётчики в Bridge UI: `bridge → URPC (под cert)` растёт когда мешевая точка форвардится через cert. `bridge → ATAK (fallback маркер)` растёт когда cert'а нет — точка идёт как `u-d-p` маркер через ATAK.

## Поведение при отсутствии cert'а (fallback)

Если в мешт залетел юзер, для которого cert ещё не импортирован:

- **PLI** — конвертируется в маркер `u-d-p` (User-Defined Point) и шлётся через ATAK на multicast. URPC получает как маркер с UID `MESH-MARKER-<callsign>`. На карте URPC появляется маркер (флажок), не иконка юзера. Точка не прыгает, callsign виден.
- **Чат** — шлётся под твоим cert'ом с префиксом текста: `[Honor] оригинальное сообщение`. На URPC выглядит как чат от `SERVER-bridge`, но автор очевиден из префикса.

Каждый fallback-PLI кидает Android-уведомление **«Импортируй cert для X»**.

## Что НЕ поддерживается в v0.2

| Фича | Статус | Когда |
|---|---|---|
| Маркеры/draw/casevac с URPC → в меш | ❌ | TAKPacket v1 не имеет полей. Будет в v0.3 (переход на TAKPacket v2, требует FW нод ≥ 2.8) |
| Личные сообщения URPC → конкретному мешевому юзеру | ❌ | Сейчас все per-cert RX игнорятся. v0.3 |
| Несколько серверов одновременно (URPC + takserver.ru) | ❌ | Vault ключит по callsign'у — два cert'а одного юзера с разных серверов конфликтуют. v0.3 |
| Шифрование cert-паролей в хранилище | ❌ | Сейчас plain в private storage (sandbox защищает от других apps). v0.3 (EncryptedSharedPreferences) |
| Lazy reconnection (открыть TLS только при активности) | ❌ | Сейчас все N persistent. До 20 юзеров терпимо. v0.3 |

## Trade-offs резюме

| | Плюс | Минус |
|---|---|---|
| Cert-per-user (импортирован) | Иконка юзера с реальным callsign'ом, точка не прыгает | Юзер должен один раз получить cert на базе |
| Fallback на маркер | Работает сразу, без cert'а | На URPC видна как маркер, не как иконка юзера |
| Чат-префикс | Автор виден в тексте | На URPC показано "от тебя", не "от Honor" |
